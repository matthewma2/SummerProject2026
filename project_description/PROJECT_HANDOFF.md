# Project Handoff

This document is a map for someone taking over the project. It explains what the project is trying to do, which files matter most, and where to continue without having to rediscover the whole repo from scratch.

For proposed renames and cleanup work, see `PROJECT_CLEANUP_PLAN.md`.

For current resolution totals and the most-mentioned work IDs, see `JSL_CITATION_STATISTICS.md`. Refresh that report after changes to stages 10 or 11 that alter merged IDs or citation assignments.

## Project Goal

The project is building structured bibliographic and citation data for early logic-related literature. The main targets are:

- A canonical database of works, authors, journals, and publishers.
- Extracted and resolved citation references from the Journal of Symbolic Logic.
- Parsed additions and corrections to Church's bibliography.
- Exportable bibliography artifacts such as BibTeX/PDF output.

The eventual research use is citation-network analysis: which logic works cite which other works, and how those citation relationships change over time.

## Mental Model

Think of the repo as five layers:

1. `databases/`: current canonical structured data.
2. `jsl_citations_pipeline/` and `jsl_citations_data/`: the most explicit pipeline, focused on JSL references.
3. `additions_and_corrections_bibliography/` and segment folders: Church additions/corrections parsing work.
4. `active_scripts/`: reusable maintenance/export scripts.
5. `old_data/`, `old_scripts/`, and `archive/`: historical inputs, experiments, and earlier versions.

When in doubt, start from `databases/`, then follow the numbered files in `jsl_citations_pipeline/`.

## JSL Citation Pipeline

Run scripts from the repo root.

```bash
python3 jsl_citations_pipeline/1_strip_internal_refs.py
python3 jsl_citations_pipeline/2_compile_references.py
python3 jsl_citations_pipeline/3_remove_duplicates.py
python3 jsl_citations_pipeline/4_match_references_to_works.py
python3 jsl_citations_pipeline/5_split_all_caps.py
python3 jsl_citations_pipeline/6a_parse_all_caps.py
python3 jsl_citations_pipeline/6b_split_by_length.py
python3 jsl_citations_pipeline/7_split_by_author.py
python3 jsl_citations_pipeline/8a_parse_with_authors.py

```

### Pipeline Files

`1_strip_internal_refs.py`

- Input: `jsl_citations_data/1_jsl_citations_original.json`
- Output: `jsl_citations_data/2_jsl_citations_cleaned.json`
- Log: `jsl_citations_pipeline_logs/2_stripped_internal_refs_log.txt`
- Removes internal back-references such as bracketed bibliography pointers, `op. cit.`, `loc. cit.`, bare `ibid.`, and `q.v.`.

`2_compile_references.py`

- Flattens the nested cleaned citations into `jsl_citations_data/3_references_cleaned.json`.

`3_remove_duplicates.py`

- Deduplicates cleaned strings into `jsl_citations_data/4_references_deduplicated.json`.
- Writes detailed removals to `jsl_citations_pipeline_logs/4_removed_duplicates_log.json`.

`4_match_references_to_works.py`

- Matches deduplicated strings against `databases/works.json` and writes unresolved strings to `jsl_citations_data/5_unresolved_references.json`.

`5_split_all_caps.py`

- Splits unresolved strings into `6a_all_caps_author_references.json` and `6b_other_references.json`.

`6a_parse_all_caps.py` and `6b_split_by_length.py`

- Parses the all-caps branch and splits the other branch into further-internal, deferred journal, and long-reference groups.
- Stage 6a writes rejected all-caps references to `jsl_citations_pipeline_logs/6a_ignored_all_caps_author_references.txt`.

`7_split_by_author.py`

- Splits `7_long_valid_refs.json` into `8a_with_authors.json` and `8b_no_authors.json`.

`8a_parse_with_authors.py` and `8b_parse_no_authors.py`

- Parses both long-reference branches into `9a_parsed_with_authors.json` and `9b_parsed_no_authors.json`.

`9_prepare_work_candidates.py`

- Resolves author IDs, rematches existing works, validates parsed records, and writes `10a_works_ready_to_add.json` and `10b_works_needing_review.json`.
- Retains particles while comparing initials, so names such as `W. V. Quine` can match `Willard Van Orman Quine` without weakening ordered-initial matching.
- Removes a trailing parenthesized publication year from an otherwise valid author segment before matching.
- Writes the prioritized unresolved-author authority report `jsl_citations_pipeline_logs/9_unresolved_authors.json`; missing people are not created automatically.
- Writes contextual and fragmentary exclusions to `jsl_citations_pipeline_logs/9_invalid_or_contextual_references.json`.

`10_merge_works_database.py`

- Safely merges reviewed candidates with `databases/works.json` into `11_merged_database.json`, adjusting colliding IDs and excluding probable duplicate works.
- Also recognizes exact titles after removing only trailing location, publisher, or year tokens already present as structured metadata.

`10b_resolve_jsl_journal_metadata.py`

- Resolves title-less references such as `This JOURNAL, vol. 13 (1948), pp. 95-106.` by querying Crossref for the JSL print ISSN and matching exact volume, year, and complete page range.
- Accepts a result only when all exact Crossref candidates converge on one work in `11_merged_database.json` by DOI or exact normalized title/year/volume.
- Caches annual Crossref responses in `jsl_citations_pipeline_logs/10b_crossref_jsl_metadata_cache.json`, so normal reruns are reproducible and do not repeat API calls. Use `--refresh` to replace cached years or `--offline` to prohibit network access.
- Writes accepted and rejected candidates, parsed fields, and rejection reasons to `jsl_citations_pipeline_logs/10b_jsl_journal_metadata_resolution.json` without modifying either works database.

`11_resolve_jsl_citations.py`

- Resolves the nested cleaned citations against the merged database and writes `12_jsl_citations_resolved.json`.
- Preserves conflict-free IDs established by parser, existing-work, candidate, and parsed-duplicate audit records instead of rematching every string from scratch.
- Consumes the exact JSL metadata matches audited by stage 10b. These matches are prevented from triggering the older adjacent-volume inheritance heuristic, because adjacent volume entries may represent distinct articles.
- Treats `this JOURNAL` as *The Journal of Symbolic Logic* during journal/volume matching.
- Resolves `ibid.`/`loc. cit.` from earlier references in the same source and conservatively inherits immediately adjacent strings beginning with `vol.`, `volume`, or `Bd.`.
- Adds `status` and `resolution_method` to every reference. Unresolved non-work strings can be labeled `internal`, `contextual`, or `fragment` without receiving a work ID.
- Keeps the unresolved-reference log as a JSON list of strings for compatibility and writes method/status totals plus ignored provenance conflicts to `jsl_citations_pipeline_logs/12_resolution_summary.json`.

Shared parsing and matching implementations used by these stages live in `jsl_citations_pipeline/_helpers/`.

### Current JSL Data Snapshot

These counts are from the current files:

- `1_jsl_citations_original.json`: 682 source entries and 7,502 references.
- `2_jsl_citations_cleaned.json`: 682 source entries and 5,716 references.
- `10a_works_ready_to_add.json`: 1,707 candidate works before final merge-time duplicate checks.
- `10b_works_needing_review.json`: 827 records needing review.
- `11_merged_database.json`: 4,858 works with unique IDs.
- `12_jsl_citations_resolved.json`: 4,219 resolved and 1,497 references without IDs, for a 73.8% raw-string resolution rate.
- Of the 1,497 references without IDs, 618 are explicitly classified as internal, contextual, or fragmentary; 879 remain genuinely unresolved.
- Stage 11 ignored 14 conflicting provenance keys rather than selecting an ID arbitrarily.
- Stage 10b examined 41 distinct complete-range `this JOURNAL` forms. It matched 24 spelling/punctuation variants representing 21 normalized references and assigned 25 occurrences; this produced 22 net new resolutions because three occurrences had already been assigned by the general heuristic.

## Active Utility Scripts

`active_scripts/build_journals_database.py`

- Reads journal names from `databases/works.json`.
- Writes `databases/journals.json`.
- Use after substantial changes to journal fields in works.

`active_scripts/build_publishers_database.py`

- Writes the curated `databases/publishers.json`.
- This is hand-curated data encoded in a script, not inferred from works.

`active_scripts/works_to_bib.py`

- Converts `databases/works.json` to BibTeX.
- Default output is `jsl_citations_data/works.bib`.
- Useful for rebuilding bibliography artifacts under `bibliography/`.

`active_scripts/extract_mind_citations.py`

- Extracts and structures citations from a Mind PDF/source using author/work data.
- Default output is `jsl_citations_data/extracted_mind_citations.json`.

`active_scripts/filter_jsl_citations_by_year.py`

- Filters JSL citation entries to sources containing `1936`.
- This looks like a narrow utility or experiment, not part of the main numbered JSL pipeline.

`active_scripts/split_jsl_unresolved_by_length.py`

- Generic split-by-length helper.
- The numbered JSL pipeline now has its own specific splitter at `jsl_citations_pipeline/6b_split_by_length.py`.

## Suggested Next Steps

1. Decide what counts as canonical output.

   The likely core is `databases/works.json`, `databases/authors.json`, and the resolved/parsed JSL outputs. Write that decision down once it is firm.

2. Review the prepared JSL work candidates before promoting the merged database.

   Start with `jsl_citations_data/10b_works_needing_review.json`. The provisional merged result is `jsl_citations_data/11_merged_database.json`; the canonical `databases/works.json` is not modified automatically.

3. Work down the unresolved queue.

   Start with `jsl_citations_pipeline_logs/12_unresolved_references.json`, then revisit `jsl_citations_pipeline_logs/6b_journal_refs.json`.

4. Clean up authority data.

   Use `further_citations/further_citation_authors_missing_in_database.txt` and unmatched parsed records to add missing authors/aliases to `databases/authors.json`.

5. Regenerate derived authority/export files after database edits.

   Run `active_scripts/build_journals_database.py`, `active_scripts/build_publishers_database.py` if publishers changed, and `active_scripts/works_to_bib.py`.

6. Add validation scripts.

   The project would benefit from a small checker that verifies unique work IDs, author IDs referenced by works, valid JSON, and required fields by work type.

## Practical Advice

Do not try to understand every file at once. Start with:

1. `databases/works.json`
2. `databases/authors.json`
3. `jsl_citations_pipeline/`
4. `jsl_citations_data/10b_works_needing_review.json`
5. This handoff document

When adding new data, preserve provenance. Keep the raw reference string, the script/manual process that produced the parsed record, and any confidence or match notes. That will save a future maintainer from having to guess whether a record is source data, a heuristic match, or a human-reviewed correction.
