# Project Cleanup And Rename Plan

This document lists confusing names, likely redundancies, and proposed cleanup steps. It is intentionally separate from `PROJECT_HANDOFF.md`: the handoff explains the current repo; this file proposes how to make the repo easier to maintain.

## Cleanup Rules

- Do renames in small batches.
- After each batch, update script paths and documentation.
- Do not delete provenance files unless they are exact duplicates or have been intentionally archived elsewhere.
- Prefer clearer names over shorter names.
- Preserve numbered pipeline files where numbering explains execution order.

`jsl_citations_data/jsl_citations.json`

- Exact duplicate of `jsl_citations_data/1_jsl_citations_cleaned.json`.
- Current status: redundant.
- Recommended action: remove it after confirming no active script still treats it as canonical input.
- Safer transitional option: rename to `jsl_citations_data/legacy_jsl_citations_cleaned_duplicate.json` for one commit, then delete later.

## Recommended Folder Renames

These are ordered from lowest risk to highest risk.

### Batch 1: Historical Folders

Current:

- `old_data/`
- `old_scripts/`
- `archive/`

Proposed:

- `archive/legacy_data/`
- `archive/legacy_scripts/`
- keep `archive/` as the parent historical area

Why:

- The current repo has both `old_*` and `archive/`, which makes it unclear whether "old" is older than "archive" or vice versa.
- Moving old data/scripts under `archive/` makes the top level less noisy.

Risk:

- Low to medium.
- Some old scripts and docs reference `old_data/` or `old_scripts/`, but these are not part of the current pipeline.

### Batch 2: Active Utility Scripts

Current:

- `active_scripts/`

Proposed:

- `maintenance_scripts/`

Why:

- "Active" is vague. These scripts are utilities for rebuilding authorities, exporting BibTeX, or running side extractions.
- "Maintenance" better distinguishes them from the numbered JSL pipeline.

Risk:

- Medium.
- Several docs and script comments mention `active_scripts/`.
- Script paths in docs need updates; actual hardcoded imports appear minimal.

### Batch 3: Canonical Data

Current:

- `databases/`

Proposed:

- `canonical_data/`

Why:

- "Databases" could mean generated, external, or final. The folder actually contains the current canonical JSON authority/work files.

Risk:

- High.
- Many scripts hardcode `databases/authors.json` and `databases/works.json`.
- This is worth doing only if we update all path references in one pass and rerun syntax checks.

### Batch 4: JSL Pipeline Data

Current:

- `jsl_citations_data/`

Proposed:

- `jsl_pipeline_data/`

Why:

- The folder contains staged pipeline inputs/outputs, not just generic JSL citation data.
- The shorter name also pairs cleanly with `jsl_citations_pipeline/`.

Risk:

- High.
- Almost every JSL script hardcodes paths under `jsl_citations_data/`.
- If renamed, update all scripts, docs, and bibliography references to `works.bib`.

### Batch 5: Church Additions Names

Current:

- `additions_and_corrections_bibliography/`
- `church_additions_and_corrections_segments/`

Proposed:

- `church_additions_pipeline/`
- `church_additions_segments/`

Why:

- The current names are long and too similar.
- Both refer to Church's "Additions and Corrections"; using the same prefix makes the relationship clear.

Risk:

- Medium.
- The parser scripts contain output paths that may also need to be updated.

### Batch 6: Church Bibliography Segments

Current:

- `church_bibliography_segments/`

Proposed:

- `church_main_bibliography_segments/`

Why:

- Makes clear that these are from the main Church bibliography, not the additions/corrections supplement.

Risk:

- Low to medium.
- Mostly a folder rename plus documentation updates.

## Recommended File Renames

## Deletion Candidates

Do not delete these until the project owner confirms they are no longer needed.

`jsl_citations_data/jsl_citations.json`

- Exact duplicate of `1_jsl_citations_cleaned.json`.
- Best deletion candidate.

`bibliography/*.errors.txt`

- Generated LaTeX/BibTeX logs.
- Keep if useful for debugging current BibTeX output; otherwise regenerate when needed.

`.DS_Store`

- macOS metadata.
- Should be added to `.gitignore`.
- If already tracked, remove from git tracking in a separate cleanup commit.

`.venv/`

- Local virtual environment.
- Should not be versioned.
- If tracked, remove from git tracking in a separate cleanup commit.

## Suggested First Batch To Actually Apply

Start with these because they reduce confusion without touching the core database paths:

1. Rename `further_citations/new_batch.json` to `further_citations/batch_input.json`.
2. Rename `further_citations/processed_batch.json` to `further_citations/batch_processed.json`.
3. Update `further_citations/process_further_citations.py`.
4. Add `.DS_Store` and `.venv/` to `.gitignore`.
5. Decide whether to remove or quarantine duplicate `jsl_citations_data/jsl_citations.json`.

After that, consider the folder renames in this order:

1. `old_data/` and `old_scripts/` into `archive/`.
2. `active_scripts/` to `maintenance_scripts/`.
3. Church additions folders.
4. `databases/` and `jsl_citations_data/`, only when ready for a larger path update.
